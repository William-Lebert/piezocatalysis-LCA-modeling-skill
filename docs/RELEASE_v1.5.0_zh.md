# v1.5.0 版本说明与回滚方案

版本：**v1.5.0**，2026-11-16。这次在 v1.4.0 的基础上增加了面向 Agent 的任务路由和阶段记录，同时加强证据链核对。

这次更新让 Agent 更容易从研究者的实际问题出发。需要先检查数据时，可以进行快速审查；需要建立模型时，可以按照引导流程处理范围、前景、映射和计算；已有结果需要整理时，可以直接生成科研交付。单项任务仍可以单独调用现有工具。

新增的可选阶段记录会保存所列输入、输出和上游记录的摘要。已登记的上游文件改变时，相关下游状态会提示不能直接复用，原有文件会保留。科研流程中并非所有依赖都能靠文件摘要自动发现，因此仍需由 Agent 和研究者核对登记是否完整，以及数据和方法是否适用。

实验数据的证据链也更严密了：逐循环清单中的来源和证据类别需要与前景记录一致。使用 `cycle-<循环编号>` 标记来源时，如果目标指向另一个已知循环，即使两个数值相同，也会提示修正。其他样品基准和原始文献或表格位置仍需人工核对。清单中的证据类别描述原活动输入；按功能单位缩放后的数量是计算结果。

本轮以合成实验数据重新检查了前景、映射、真实 openLCA 计算、图表和科研交付。在受控数据库副本中，两个情景的 32 类结果与已有合成基准一致；交付及其重建各有 35 个文件通过摘要检查。模型仍含代理和未解决的催化剂处置，因此这些结果只用于测试流程。自动测试及复核范围见 [验证报告](verification-report.md)。

## 使用原有材料

如果现有逐循环清单中的来源或证据类别与前景不一致，新版会拒绝继续审查或整理。请核对原始依据、修正前景，再生成新的清单、manifest 和受影响的下游报告。已知循环基准与目标循环不一致时，也需要更正证据链接。详情见 [迁移说明](migration-notes.md)。

## 回滚与引用

如需回到已发布版本，先保存当前研究输入、输出和开发副本，再将 v1.4.0 标签检出到独立目录；标签提交为 `879f3d7bfa2ff295014f70e084aa1bf315498d30`。旧版不一定理解新增阶段记录，应保留这些记录供新版使用。若正式发布后需要恢复仓库代码，应基于实际发布提交创建新的回滚提交，不移动公开标签。

Zenodo 版本 DOI 以实际归档为准；本地数据库和受许可约束的衍生结果不纳入公开包。
