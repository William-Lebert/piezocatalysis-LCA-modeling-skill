# v1.7.10 维护候选

openLCA 2.7.0 的工作线程可能在过早释放后重新登记计算结果。真实 openLCA 的本机复现中，服务先确认释放，再将已完成的结果登记到同一个 ID。修复后，客户端遇到仍为已排程的计算，会在独立的清理窗口内等待后台计算结束，再请求释放。等待上限为 30 秒，超限时仍尝试释放，并报告确认不足。

手动 IPC 验收复用由 33 个独立供应过程组成的虚构数据库。用同一份数据库在两端运行 `tests/integration_openlca_manual_ipc.py`，以同一组 UUID 对照 LCIA、贡献、总清单流及快照。脚本还用 1 ms 等待预算触发超时，确认超时结果在释放后及恢复计算后均不可用。[Windows 手动 IPC 验收](../platforms/windows/README.md#手动-ipc-真机验收)

macOS 真实 openLCA 对照已通过。两个计算量的 LCIA 为 56.0 和 112.0，快照稳定，超时 ID 在恢复计算后仍不可用。该对照以本机 IPC 调用原生查询路径。Windows 真机验收待可用会话，本地候选保留对照数据和可执行入口。
