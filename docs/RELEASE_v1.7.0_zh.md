# v1.7.0 版本说明

这次更新从一份实验记录开始。Agent 可以把样品、重复测量的取值理由、检出限、运行时间和能耗对应到逐循环清单。到了催化剂最后一次回收，仍可追溯它是留存了、进入处置，还是去向待查。处置映射会核对干基质量、处置依据和 openLCA 中实际接收废物流的过程。

做背景映射时，可以先核对实际交换的单位和流属性，再检查指定基本流在所选影响类别中有没有表征因子。做敏感性分析时，Agent 可以把功率、表现和寿命情景逐个放进 openLCA 重算。更换地区电网时，交付记录会保留各情景的实际供应连接。清单、计算、图表和方法说明随同整理，后续可以在对应数据库中复算。

我们用本机 openLCA 和 ecoinvent 跑过合成逐循环案例，也以 BiOCl 制备及产 H₂O₂ 的文献清单验证了功率和电网情景。BiOCl 以论文报告的产量为基准，五水硝酸铋继续作为待补数据。案例原文、专有背景数据及其计算结果保存在本地研究环境，公开包使用合成示例。[BiOCl 文献](https://doi.org/10.1016/j.watres.2025.123977)

## 升级时需要做什么

- 有末端处置的逐循环项目，先核对 `final_recovered_fate` 中的路线、来源和证据类别。需要接入处置过程时，由原前景重新生成清单和 manifest，再重做映射。
- 开发预览阶段生成的情景套件需用原规格重新采集，补上根过程到各阶段参考交换的核对记录。再重建受影响的图表和交付。
- 如需使用旧的逐循环情景绑定、H₂O₂ 或科研交付记录，请按各入口的[迁移说明](migration-notes.md)核对格式和范围。

## 回滚方案

**回滚目标为 v1.6.0**。Git 标签指向 `776e00b73ac275bac736d13806ac9bbaa0529016`。可以从已核验的 GitHub 标签或 Zenodo 归档取得旧版，安装到一个单独目录，然后在 Agent 环境里切回旧版 Skill。[GitHub v1.6.0](https://github.com/William-Lebert/piezocatalysis-LCA-modeling-skill/releases/tag/v1.6.0) · [Zenodo v1.6.0](https://doi.org/10.5281/zenodo.24333330)

1. 保留候选版本的前景、清单、映射表、证据、交付包和对应数据库副本。旧版运行选用原来的输入和已知可用的库副本，输出写入新目录。
2. 运行 v1.6.0 随附的测试，再用一个旧版兼容的逐循环合成案例检查清单、映射和计算。候选版的 `reported_production` 和情景套件保留供新版复算，回退时勿转成其他产量口径。
3. 发布后如需回退仓库，用新的反向提交恢复受影响的代码，保留已有标签、Release 和 DOI。若需重新分发修复版本，使用新的补丁标签及相应归档。
