# 架构与测试复核：v1.1.1 候选

基线：已发布 v1.1.0（Git 提交 `2398898`）；复核日期：2026-11-13。v1.1.1 的 GitHub Release 和 Zenodo 版本 DOI 须另行核实。

## 架构

项目是 Python 标准库为主的科研工作流与技能文档，而不是完整 LCA 计算引擎。主要链路是：

1. `validate_model_spec.py` 校验模型规格的结构子集；`validate_inventory.py` 校验前景清单的必填字段与数值。
2. `audit_and_scale_inventory.py` 读取清单、映射和参数，审查单位及来源并按污染物去除功能单位缩放；它依赖 `validate_inventory.py` 中的公共枚举，不获取背景数据库或影响因子。
3. `openlca_readonly.py` 通过本机 IPC 查询现有产品系统并读取 openLCA 计算结果；对已有服务，服务端的网络访问与写权限不受客户端白名单保护。可选的 macOS 2.7.0 自动启动以临时副本和独立服务端限制运行，细节见 openLCA 工作流。
4. `sensitivity_report.py` 使用外部已计算的绝对结果及不重叠贡献，进行单因素情景近似；它不连接 openLCA，也不替用户确认科研可比性。
5. `piezocatalysis_calculations.py` 提供独立的去除率、能耗及缩放辅助计算。Brightway 示例在单独环境运行，lca_algebraic 与 premise 未集成。

数据边界：仓库中的案例为合成数据；真实背景库、授权、功能单位、系统边界及参数来源仍须由研究者独立核实。openLCA 的单位、数据库身份、方法及元数据有用户声明部分，连接成功不代表结果科学有效。

## 本次修复及兼容性

- 不同影响类别的单位和数量级不相同，固定 `1e-12` 的绝对容差会将很小的非零影响与零视为一致。敏感性核对改为相对容差 `1e-9`，openLCA 贡献核对改为 `1e-6`，均使用零绝对容差；零总量必须与零分项和精确一致。更严格的检查可能拒绝低精度的旧输入或产生更多警告，接近零且存在抵消时应提高数据精度并人工核查。
- 之前清单校验器把方向和证据类别按不区分大小写处理，但缩放器区分大小写。现在两者一致接收大小写变体，并在缩放输出使用小写规范值。
- 仅有表头的空清单现在报错。计算辅助函数及复合批次缩放在非零结果下溢为零时拒绝输出；允许的真实零值仍有效。
- README 补充已发布 v1.1.0 的具体版本 DOI；CITATION.cff 不预填尚未取得的 v1.1.1 版本 DOI。

## 测试方法与局限

使用标准库 unittest 全量测试、命令行帮助检查、Python 编译检查、合成端到端案例和独立手算锚点。新增回归覆盖极小影响与零的错误核对、空清单、大小写一致性、下溢及零边界；还运行两组合成清单至部分影响情景的贯通案例，结果见 `两组合成运行_v1.1.1.md`。

openLCA 的标准自动测试使用本机 JSON-RPC 模拟服务，覆盖方法白名单、错误、超时、结果回收和贡献核对。另运行真实 openLCA 2.7.0 的隔离合成数据库：自动启动、只监听本机、服务端拒绝写入/删除、两次需求计算结果分别为 3.2 和 6.4、父进程强制结束时服务退出，并核对源合成数据库的文件内容哈希未变。本机 ecoinvent 通过临时副本读取 35 个流属性描述；源文件大小及修改时间未变，但未计算真实产品系统。此前 Brightway 虚构案例与手算一致，本次未重新运行 Brightway。尚未测量代码覆盖率、进行多操作系统/Python 版本矩阵、负载测试、真实数据库完整回归、外部安全审计或科学同行评审；不能根据通过的测试数量推断覆盖百分比或宣称所有缺陷已修复。
